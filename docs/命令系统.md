# 命令系统

状态：**已落地**  
协议：MCPE 1.1.x / protocol 113  
前缀：`/`（聊天消息以斜杠开头则不分发到公共聊天）

## 入口

1. 出生后发送 `AvailableCommands`（**0x4e**，PocketMine `AVAILABLE_COMMANDS_PACKET`），让 1.1 客户端承认 `/give`、`/summon`、`/gamemode`、`/world`、`/coord`、`/help`
2. 聊天 `TextPacket`：消息以 `/` 开头 → 去掉前缀后分发
3. `CommandStep`（**0x4f**）客户端命令 UI 提交 → 拼成命令行后走同一套分发

实现位置：

- `internal/command/`：注册表、`/give`、`/summon`、`/gamemode`、`/world`、`/coord`、`/help`、物品/实体解析
- `internal/server/server.go`：`handleChat` / `dispatchCommand` / 下发 AvailableCommands
- `internal/protocol/packets/command_step.go`、`available_commands.go`

## `/give`

用法：

```text
/give <玩家> <物品id[:meta]|名称> [数量]
```

- 玩家：在线用户名（不区分大小写），或 `@s` 表示自己
- 物品：数字 `1`、`1:0`，或常用名如 `stone`、`dirt`、`wool`（可带 `minecraft:` 前缀）
- 数量：省略默认 64，最大 64
- 不支持 NBT

示例：

```text
/give @s stone 32
/give Steve 35:1 16
/give Steve wool
/help
```

物品会先堆叠到已有同 ID/meta 的格子，再放入空槽；成功后刷新目标背包。执行者与目标都会收到系统回执（`TextTypeRaw`）。

## `/summon`

用法：

```text
/summon <实体名|id> [x y z]
```

实体清单、别名和本轮限制见 [生物实体.md](生物实体.md)。

示例：

```text
/summon zombie
/summon zombie ~ ~1 ~
```

## `/gamemode`

用法：

```text
/gamemode <模式> [玩家]
```

别名：`/gm`。本轮只支持生存与创造，人人可执行（与 `/give` 相同，不查权限节点）。

模式（不区分大小写）：

- 生存：`0` / `survival` / `s`
- 创造：`1` / `creative` / `c`

省略玩家则对自己；指定玩家时与 `/give` 一样支持在线用户名和 `@s`。`2` / `3`（冒险、旁观）返回未知模式。

切换时会写入玩家存档字段、下发 `SetPlayerGameType`、同步 `AdventureSettings`（创造开飞行，生存关飞行并落地），并发送创造选取栏（window `0x79`）。不在切换时清空背包。

示例：

```text
/gamemode 1
/gm 0
/gamemode creative Steve
```

## `/world`

用法：

```text
/world <世界名>
```

无别名。加载哪些世界由 [server.properties](持久化存储.md#选择启动时加载的世界) 决定。`/world` 列出实际加载的目录名，`/world Mines` 等命令可直接传送到自定义世界。跨维度会发 `ChangeDimension` 并重发区块；同维度只传送并重发区块。人人可执行，切世界不清背包。

世界名不区分大小写，先匹配实际目录名，再尝试下面的别名；目标必须已加载：

- 主世界：`overworld` / `world` / `flat` / `超平坦` / `主世界`（落到配置里的 `WorldName`，默认磁盘名 `world`，维度 0）
- 空岛：`sky` / `空岛`（磁盘目录 `sky`，维度 0，chunk `(0,0)` 一整列 16×16 草土岛，出生 `(8,64,8)`）
- 海洋：`ocean` / `海洋`（磁盘目录 `ocean`，维度 0，y<64 静止水、y≥64 空气，原点 16×16 小岛，出生 `(8,64,8)`）
- 地狱：`nether` / `hell` / `地狱` / `下界`（磁盘目录 `nether`，维度 **1**；新建时生成岩洞和岩浆海）
- 末地：`end` / `the_end` / `末地`（磁盘目录 `end`，维度 **2**；新建时生成末地石岛和黑曜石柱）

两个命令都传送到目标存档记录的出生点；旧虚空岛存档的坐标与地形不变。

未知名报错。已在目标世界则提示已经在此。成功后传送到该世界出生格的水平中心；发给玩家的位置 Y 含眼高。

示例：

```text
/world sky
/world overworld
/world 海洋
/world 地狱
/world 末地
```

## `/coord`

用法：

```text
/coord [on|off]
```

别名：`/coords`、`/pos`。不带参数就是取反，方便快速开关。**默认开启**，进服就显示。参数认中文（`开`/`开启`/`关`/`关闭`），命令名一律英文。

在**快捷栏正上方**显示一行实时坐标，每 200ms 刷新一次：

```text
主世界 X: 12.5 Y: 64.0 Z: -3.2
```

关闭时发一次空字符串把那一行清掉，不留残影。

### 为什么不用原版 `showcoordinates`

原版 Bedrock 有 `showcoordinates` 游戏规则，打开后客户端自己在左上角画坐标，不需要服务端每帧推送。但**这个规则是 1.2 才加的**，protocol 113（1.1.7）上没有：

- `pocketmine服务器参考` 里 `StartGamePacket.php:89` 是 `putUnsignedVarInt(0); //TODO: gamerules` —— 规则表恒为 0 条
- `ProtocolInfo.php:110` 只有 `GAME_RULES_CHANGED_PACKET = 0x49` 常量，没有对应的包类实现

所以只能服务端定时推。用的是 `TextPacket` 的 `TYPE_TIP`（**4**），位置和 PocketMine `sendTip()`（`Player.php:4119`）一致 —— 快捷栏正上方，也是 1.1 客户端唯一合适的常驻文字位。同位置的 `SetTitlePacket::TYPE_ACTION_BAR` 也可以，但本项目还没实现 `SetTitlePacket`，TIP 现成可用。

刷新频率 4 tick（200ms）：客户端 tip 会自己淡出，间隔太长会闪。每 200ms 一个 `TextPacket`，对 1.1 客户端不算负担。

实现位置：`internal/command/coord.go`（命令）、`internal/server/coords.go`（推送与文本），开关状态挂在 `Player.CoordsShown` 上。**注意：这个开关目前不存盘**，每次进服回到默认的开启状态。

## 协议包 ID 修复（2026-08-24）

现象：输入 `/give @s stone 10` 时，客户端红字「未知指令。请使用 /help 来查看指令列表」，服务端控制台没有任何命令日志。

结论：不是 OP。登录已发 Operator，`/give` 也不查权限。1.1 客户端在 `StartGame.commandsEnabled=true` 时会**本地**校验斜杠命令；收不到正确的 `AvailableCommands` 就不会把 `CommandStep` 发给服务端。

对照 PocketMine 1.1 `ProtocolInfo.php`（CURRENT_PROTOCOL=113）：

| 包 | 正确 ID | 曾误写为 | 误写实际含义 |
|---|---|---|---|
| `AvailableCommands` | **0x4e** | 0x4b | `AddItem` |
| `CommandStep` | **0x4f** | 0x4c | `BossEvent` |

0x47 之后曾漏掉 `ReplaceItemInSlot(0x48)`、`Camera(0x4a)`、`AddItem(0x4b)`，后面整段 ID 错位。已按 PocketMine 对齐，见 `internal/protocol/info.go`。

`CommandStep.inputJson` 若是对象，按 JSON 出现顺序取参数值（与 PHP `foreach` 一致），不要按 key 字母排序。

复测：重新编译进服后，`/give @s stone 10` 控制台应出现 `执行 /give @s stone 10`，快捷栏出现石头。
