# 方块行为

放置、挖掘后的连锁反应、开关门、液体流动、沙子下落、作物生长……这些都是同一套机制。
规则写在 `internal/blockrule`，服务端 `internal/server` 负责落地、广播、掉落和加锁。

## 分工

`blockrule` 是纯逻辑：只通过 `View` 读世界，返回"要改哪些格子"，不碰网络、实体和锁，所以能脱离服务器单独测试。

```go
type View interface {
    Block(pos Pos) (id, meta byte)   // 没加载的区块、超出高度都按空气返回
    Loaded(pos Pos) bool             // 区块是否已在内存里
}

type Change struct {      // 一格方块的改动
    Pos Pos; ID, Meta byte
    Drop bool             // 原来的方块"自己掉下来"：按空手结算掉落和破坏粒子
    Fall bool             // 原来的方块变成一个下落中的实体（沙子、沙砾）
}
type Update struct {
    Changes   []Change
    Schedules []Schedule  // 过 Delay 个 tick 再评估某一格
}
```

服务端有两种 `View`：

- `loadingView`：读到没加载的区块会把它加载出来。只给玩家主动的操作用（放置，挖掘时找另一半），落点在视野边缘时需要。
- `peekView`：只读内存里已有的区块，绝不触发生成或读盘。邻居更新、定时任务、随机刻、下落、液体都用它。
  否则挖一个方块可能把相邻的一整片空区块生成出来，而区块卸载还没做，内存会一直涨。

## 加锁

`Server.blockMu` 保护"读方块再改方块"的整段流程：放置、挖掘、交互、级联、各种 tick。
**它必须最先拿**，里面再拿 `mu`、玩家锁、世界锁，反过来会死锁。
带 `Locked` 后缀的函数（`settleBlocksLocked`、`applyChangeLocked` 等）要求调用方已经持有它。

## 点击一个方块之后发生什么

`handleUseItem` 按顺序尝试，前一步吃掉点击就不再往下：

1. 打开箱子、工作台
2. `interactBlock`：点到门、活板门、栅栏门、拉杆、按钮 → 切换状态（潜行时跳过）
3. `useItemOnBlock`：拿着锄头、骨粉点方块（潜行时跳过）
4. `placeHeldBlock`：手持方块的放置，`blockrule.Place` 算落点和 meta

放置被拒时只把真实方块发回给放置的人，不向全服广播。出生点保护、距离、背包有没有、实心方块不能放进自己的身体，
都在 `placementRejection` 里逐项检查。

## 级联：一个方块变了，周围怎么办

`settleBlocksLocked` 是广度优先的：把变了的格子和它的六个邻居排进队，逐个调
`blockrule.OnNeighborUpdate`，结果里真正变了的格子再把自己和邻居排进去，直到没有新变化。
单次最多评估 4096 格，超了就中止并记警告，防止规则互相触发卡死 tick。

`OnNeighborChange`（"这一格要不要掉下来"）覆盖：火把、花、树苗、高草、枯萎灌木、蘑菇、甘蔗、仙人掌、作物和瓜茎、
拉杆、按钮、门/床/双层植物（缺了另一半，或下半脚下撑不住）、沙子/沙砾（脚下是空气、液体或火）、耕地（上面压了实心方块）。
`OnNeighborUpdate` 在它之上多给液体排定时评估。

**遇到没加载的邻居一律保守处理**，当成"没问题"。否则区块边上的火把会因为读到空气被打掉。

## 定时任务

`Server.scheduled` 是 `{世界, 坐标} → 到期 tick` 的队列，每 tick 处理到期的，上限 256 个，剩下的顺延。
同一格重复排队保留更早的到期时间，所以连点按钮不会把弹回越推越晚。
目前用在：按钮弹回（石 20 tick、木 30 tick）、液体流动（水 5 tick、岩浆 30 tick）和火焰。打火石点火后等待 30–40 tick，蔓延产生的新火 30 tick 后首次检查；随机刻可以重新唤醒卸载或重启后留下的火。

**火焰**：默认 `fire-spread=off`，火不老化也不烧木头，但失去支撑且没有可燃邻居仍会灭。开启后火龄最高 15，每次有 1/3 概率增长；普通实心地面且周围无燃料时，旧火龄超过 3 就灭，地狱岩上可以一直烧。先用 BurnAbility 判断是否烧掉六面的燃料，再用剩余燃料的 BurnChance 判断附近空气能否着火。空气范围是水平各一格、向下一格至向上四格；越高概率越低，难度越高概率越大。
队列不存盘，重启后丢失；停在按下状态的按钮点一下会重新排上队。

## 各部分要点

**放置** `place*.go`：楼梯朝向跟着玩家偏航角，点方块底面或侧面上半部分时倒置；原木按点击面分竖直/横向；
半砖点顶面放下半、点底面放上半、点侧面看高度，同种半砖叠上去合成双层；箱子熔炉正面朝向玩家；
火把点不透明方块的顶面/侧面贴着放；活板门、栅栏门、拉杆、按钮各有自己的 meta 规则。
门、床、双层植物占两格，`placeMulti`；种子、门、床这类物品 ID 大于 255 的，`BlockForItem` 查表变成方块。

**配对** `pair.go`：`PairedHalf` 找两格方块的另一半，种类、上下（头脚）位、床朝向、植物品种都要对上。
玩家挖其中一半，另一半在同一事务里一起拆，掉落按玩家手持物结算；门的下半、床头、双层植物的上半才有掉落，
所以不管先挖哪半一共只掉一个。床的颜色在物品 meta 里，放置时写进两格的方块实体，掉落时按方块实体取。

**下落** `gravity.go`、`entity/falling_block.go`、`server/falling.go`：沙子脚下空了，原位置变空气并生成 `FallingSand` 实体，
出生包带 variant（方块 ID 放低 8 位、meta 放上面）。每 tick 重力 0.04、阻力 0.02，并把这一步经过的每个落脚面都查一遍，
不是只看终点，否则接近终端速度时会穿过薄薄一层地面。落地后落点能顶替就放回方块，被占着（火把）就掉成物品；
掉到 -16 以下当作掉进虚空直接消失。

**液体** `liquid.go`：水位用 meta，低 3 位 0 是源头、1~7 越远越浅，bit 3 是往下掉的水柱。每次定时评估：
先按四周重算自己的水位，再往下流，脚下流不动再往"最该去的方向"铺开（最多 4 格落差搜索，岩浆 2 格）。
水旁边两个源头且脚下是实心方块，就地变成新的源头。岩浆旁边有水：源头变黑曜石，水位 1~4 变圆石；岩浆流到水上，水那格变石头。
流进火把这类方块会冲掉它并掉落。液体把世界之外和没加载的区块当墙。

**随机刻** `random.go`、`server/random.go`：每个在线玩家每 tick 在周围 4 个区块里抽 12 个区块，每个有数据的子区块抽 3 个位置，
命中参与随机刻的方块才评估。作物三分之一机会长一个阶段；瓜茎长满后挑一个方向结果；甘蔗、仙人掌 meta 数满 15 往上接；
草试四次、菌丝试一次，把附近裸露的泥土变成草/菌丝。随机源作为参数传入，测试里换成固定序列。

**物品使用** `itemuse.go`、`farmland.go`：锄头点草/泥土变耕地，磨损 1 点；骨粉对作物加 2~5 阶段、对草方块撒一把花草；
耕地上面压了实心方块变回泥土；落地时脚下是耕地，落差减 0.5 就是踩坏的概率。

**告示牌** `place_sign.go`、`world/sign.go`、`server/signs.go`：点顶面放立牌，meta 是 `floor((偏航+180)*16/360+0.5)&15`，
和楼梯一样跟着玩家转；点侧面放贴墙牌，meta 直接就是被点击的面，背后靠 `meta^1` 那一面撑住；点底面放不了。
立牌脚下、贴墙牌背后变成空气就掉下来，水、火把、花都不算没支撑（只有空气才算）。
放牌时同时建方块实体，记下放牌人的 UUID 作为编辑权；客户端发 `BlockEntityData` 写字，
要过这几关才收：区块已加载（Peek，不加载）、那格是告示牌方块实体、够得着、不是旁观、不在出生点保护、
NBT 读得出来且 `id` 是 `Sign`、他就是放牌的人而且还没写过。四行字去掉格式码、控制字符、私用区字符、非法 UTF-8，
每行截到 32 字。写完清掉编辑权，所以一块牌只能由放它的人写一次；重启后编辑权不保留（不存盘），字存盘。
任何一关没过都把牌子真实的样子发回给这个玩家，客户端本地多出来的字会被覆盖掉。

## 方块属性表

固体、透明、可替换、可流入、燃烧值来自参考端各 `Block` 类，由 `scripts/gen_pm_blockprops` 按继承链提取，
生成 `internal/blockrule/props_table.go`（别手改）。依赖 meta 的属性（雪片、双层植物的可替换，台阶的燃烧值）在 `props.go` 里单独处理。
参考端的 158 号木台阶误继承了台阶的燃烧判断，这里按原版固定可燃。

## 和参考端的差异

- 漏斗连接熔炉时区分槽位：从顶部投入原料，从侧面投入燃料，从底部取成品，成品格为空时还可以取走烧完岩浆留下的空桶。参考端的 [Hopper::onUpdate](../pocketmine服务器参考/src/pocketmine/tile/Hopper.php) 把熔炉当作普通容器，可能取走未烧的原料或向成品格塞东西。其他容器沿用参考端顺序：先收整栈掉落物，再从上方取一件，最后向出口送一件；正下方有漏斗时由它来取。一次成功的容器搬运后跳过八次更新，期间仍能吸取地上物品。

- 树苗自然长树：所在格总光至少为 8 时，每次随机刻有 1/7 机会推进；第一次置成熟位 `0x08`，第二次尝试成树。总光取昼夜折算的天空光和方块光中的较大值。骨粉跳过亮度和成熟阶段，空间不足时仍消耗一份。草、泥土、耕地和灰化土可种树。
- 草上方亮度低于 4 且方块至少滤掉三级光时，草退化成泥土；蔓延需要上方亮度至少为 9，目标泥土上方至少为 4。冰和薄雪看六个邻格的**方块光**，达到 12 分别变成水源和空气。阳光本身不会融冰。参考端只在冰的随机刻中实现了融化，薄雪是本服补充。
- 树形按[参考端生成器](../pocketmine服务器参考/src/pocketmine/level/generator/object/Tree.php)：橡树有 1/10 概率长成带分枝的大橡树，白桦有 1/39 概率增高五格，云杉有锥形树冠；丛林木、金合欢和深色橡木沿用该分支的单干树形，无需 2×2 树苗。Go 不复刻 PHP 随机数序列；大橡树斜枝按方块中心连线，具体树形不保证逐格相同。
- 树苗只在可用空间内生成整棵树。检查或写入涉及未加载区块、超出高度时保留树苗；树冠不替换建筑，也不改已有叶子的放置标志。原木与树冠重叠时只广播最终的方块，新树叶不会因为本次生成被立即标成待腐烂。

- 液体按水、岩浆两大类比较水位，参考端只认完全相同的方块 ID，静水(9)和流动水(8)混着会互相不认。
- 甘蔗长高时，上面第一格不是空气就停，参考端会接着看更上面一格，可能在石头上方接出一截。
- 骨粉不会被成熟的作物吃掉。
- 参考端 [Fire.php](../pocketmine服务器参考/src/pocketmine/block/Fire.php) 的一处分支烧掉火源本身、新火龄用了 `max(15, ...)`，助燃邻居还漏扫东侧。Go 烧掉目标燃料、限制火龄不超过 15，并检查六个方向。打火石点在石墙侧面、火的位置无支撑也无燃料时不会损耗。
- 红砂岩半砖按各自的 ID 合并，参考端拿普通半砖的 ID 去比，永远合并不上。
- 沙子下落、骨粉撒草、液体冲掉方块，参考端是直接改方块，这里统一走 `Change` 再落地，掉落和广播因此一致。
- 耕地踩坏、创造模式也会踩，是按原版加的，参考端没有。
- 参考端的透明表把耕地和液体算透明：花种在耕地上要单独放过；水底下不该长草，要单独排除。
- 大箱子拆掉一半，这里立刻把剩下那半重画成单箱，并关掉开着两半的窗口；参考端不主动重画，剩下那半等下次被打开时才发现配对失效。
- 参考端打开箱子前要求头顶是透明方块（自己和搭档都查），这里没做；没有真实客户端对照原版行为，需要时再加。

## 已知缺口

- 没有桶，玩家还不能取放水和岩浆；打火石可以点火，但尚不能激活下界门。尚未接入天气灭火和 TNT 引爆。
- 自然树叶受邻居变化影响时设置 meta 的 `0x08` 位，随机刻再查支撑。从叶子沿同组树叶最多水平走三步，或在三步以内最后向下找原木；ID 18 的叶找 17，161 找 162。找到后仅清标记，不触发新的级联；找不到则按空手掉落，并通知相邻叶。路径通向未加载区块时保留标记，留待下次随机刻。玩家放置的树叶有 `0x04` 位，不腐烂。
- 直射天空光由高度图决定；通过侧面开口照进隧道时，每走一格空气衰减一级，穿过一格水衰减三级。遮住开口后重新计算。卸载的邻区不提供光，也不会因传播被重新加载。游戏内动态显示尚未用 1.1.x 真机验证。
- 铁砧、混凝土粉末、龙蛋也会下落，只做了沙子和沙砾。下落中的方块不存盘，关服时正好在掉的会丢一块。
- 落脚判定用"实心"，落在台阶楼梯上按整格高度算。
- 打火石已有点火音效，其他方块未全面接入音效。没有红石信号传递（拉杆、按钮现在只改自己的状态），没有水流对实体的推力。
- 没有真实客户端验证过朝向、开关门动画、下落动画是否平滑，meta 位布局按参考端公式移植。
- 没人的区块会被卸载（见 `internal/server/chunksweep.go`），里面的东西只有区块在内存里才会动：熔炉暂停烧制，随机刻和液体流动停下，掉落物停在原地不再下落也不会被捡，下落中的方块和已排队的定时任务（比如按钮弹回）如果恰好碰上卸载就丢了，要等有人回来再点一下。定时任务队列本来就不存盘，这是同一类缺口。
- 陷阱箱放下时没有朝向（meta 恒为 0）：参考端 `TrappedChest::place` 和箱子一样按玩家朝向设 meta，这里还没跟上。
  陷阱箱也不是容器方块，点它不会开窗，要等红石（第 23 项）一起做。

## 加一种新的方块行为

1. 属性表里没有的话，先看 `props_table.go` 有没有这个方块；缺了就改生成器重新生成。
2. 要在被点击时反应：`interact.go` 的 `Interact`。要在邻居变化时反应：`neighbor.go` 的 `OnNeighborChange`。
   要延迟反应：返回 `Schedule`，在 `OnScheduled` 里评估。要随机生长：`random.go` 的 `OnRandomTick` 并加进 `IsRandomTicked`。
3. 规则只读 `View`、只返回 `Change`。没加载的邻居按"没问题"处理。
4. 测试放在 `blockrule` 里，用 `helpers_test.go` 的 `mapView` 搭一个小世界，预期值按参考端源码手算；
   需要整条链路时在 `server` 里用 `placeTestSetup` 起一台不联网的服务器。
