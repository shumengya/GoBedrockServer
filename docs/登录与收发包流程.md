# 登录与收发包流程

## 登录流程

```
Client → LoginPacket (0x01)
Server → PlayStatus LOGIN_SUCCESS (0x02)
Server → ResourcePacksInfo (0x06, 空)
Client → ResourcePackClientResponse HAVE_ALL_PACKS (0x08)
Server → ResourcePackStack (0x07, 空)
Client → ResourcePackClientResponse COMPLETED (0x08)
Server → StartGame (0x0b)
Server → SetSpawnPosition / SetTime / UpdateAttributes / AdventureSettings
Server → PlayerList ADD (0x3f, 全服在线玩家含自己；同时把自己加进别人的列表)
Server → CraftingData (0x35, 全部配方)
Client → RequestChunkRadius (0x45)
Server → ChunkRadiusUpdated (0x46)
Server → FullChunkData × N (0x3a, 当前列状态)
Server → PlayStatus PLAYER_SPAWN (0x02)
Server → AddPlayer (0x0c, 与同世界玩家互发) + 广播加入提示
Server → ContainerSetContent (0x34, 45 格 + hotbar 映射 9–17)
```

登录阶段在发出任何游戏状态之前依次检查：名字封禁、IP 封禁、白名单、人数上限。被拒时只发 `Disconnect`（带原因），不先发 `PlayStatus` 失败包，否则客户端会弹通用的「无法连接」盖掉原因。

## 常见交互

- **放置**：`UseItem (0x23)` → 碰撞箱检测（禁止放进自身脚/头）→ `World.SetBlock` → 广播 `UpdateBlock (0x16)`。
- **破坏**：`PlayerAction` 发裂纹/打击粒子（`LevelEvent 0x1a`），`RemoveBlock (0x15)` 改空气并广播破碎粒子 + `UpdateBlock`。
- **进食**：客户端吃的过程中周期性发 `EntityEvent EATING_ITEM (57)`，服务端转给同世界玩家看食物碎屑；吃完发 `EntityEvent USE_ITEM (9)`，服务端自己校验后才扣物品、回饥饿，再用 `UpdateAttributes` 只下发饥饿相关三项。
- **合成**：客户端发 `CraftingEvent (0x36)`（配方 id + 摆在格子里的材料 + 声称的产物）。服务端按 id 找配方，匹配摆放并确认背包里真有这些料，产物以配方为准。校验不过就整包重发背包，客户端本地多画的产物会消掉。
- **客户端杂包**：`LevelSoundEvent (0x19)`、`Interact` 等已解码并忽略（不再 WARN）。`ContainerSetSlot (0x32)` 写入玩家背包后再存盘。
