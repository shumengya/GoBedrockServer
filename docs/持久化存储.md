# 持久化存储

状态：**已落地**（2026-08-23）  
协议：MCPE 1.1.x / protocol 113  

自定义格式，**不兼容** PocketMine 地图或原版 LevelDB。

## 目录

```
data/
  players/
    <uuid>.json
  worlds/
    world/             # 主世界（超平坦，维度 0）
      world.json
      tiles.json       # 箱子 / 床
      entities.json    # 掉落物
      r.<rx>.<rz>.gmr  # 区块，直接放在世界根上
    sky/               # 空岛（维度 0）
      world.json
      tiles.json
      entities.json
      r.<rx>.<rz>.gmr
    ocean/             # 海洋（维度 0）
      ...
    nether/            # 地狱（平级世界，维度 id 1）
      world.json
      tiles.json
      entities.json
      r.<rx>.<rz>.gmr
    end/               # 末地（平级世界，维度 id 2）
      ...
```

- **一个世界 = 一个维度 = 一个文件夹**：`worlds/<世界名>/` 就是一个世界的全部内容，元数据、方块实体、掉落物、区块都在这一层，不再往世界里面套 `overworld/`、`nether/`、`the_end/` 子目录。
- 玩家与地图分开：换图、备份世界不影响背包。
- 五个世界平级：主世界、空岛、海洋、地狱、末地各自一个文件夹，地狱/末地不是主世界的子目录。
- 世界与维度的对应靠 `world.json` 里的 `generator` 决定：`flat`/`sky`/`ocean` → 维度 0，`nether` → 1，`end` → 2。区域文件路径不再跟 generator 挂钩，改 `generator` 不会把区块"挪走"。
- 地狱、末地进服和 `/world` 传送会带原版维度 id（`StartGame.Dimension` / `ChangeDimension` 0x3d）：地狱 1、末地 2。空岛和海洋仍是维度 0，只重发区块。
- 配置：`DataDir` 默认 `data`，`WorldName` 默认 `world`，`AutosaveSeconds` 默认 `30`（世界），`PlayerSaveSeconds` 默认 `600`（玩家背包）。
- `data/` 已加入 `.gitignore`。

### 旧目录自动收纳

早期版本把区块存进 `worlds/<世界名>/<维度名>/`，世界被拆成两层。现在打开世界时会自动扫描 `overworld` / `nether` / `the_end` 三个旧目录，把里面的 `.gmr` 搬到世界根上，空掉的旧目录删掉；同名文件已存在时保留根上那份、跳过，避免陈旧区域文件覆盖新数据。旧目录里还有非 `.gmr` 文件就原样留着。迁移数量会打日志：`世界 X 收纳了 N 个区域文件(旧维度子目录 → 世界根)`。

## 区块滴发

1.1 客户端扛不住一次塞满视距（radius 4 → 81 列），尤其是海洋这种胖列。服务端按距离排队，**每 tick 最多发 4 列**，**发出之后**才记入 `SentChunks`。出生和 `/world` 传送会先把玩家定住，近处大约 16 列到齐后再发 `PlayStatus PLAYER_SPAWN` 并解锁。同维度切世界不会伪造 `ChangeDimension` 加载屏（PocketMine 也一样）。已经在玩时再收到 `RequestChunkRadius` 只更新视距并补队列，不会把整套出生包再发一遍。

RakNet 出站队列满时区块包会等待最多 2 秒，不再静默丢掉。

## world.json

```json
{
  "name": "world",
  "seed": 12345,
  "spawn": [0, 5, 0],
  "time": 0,
  "generator": "flat"
}
```

`generator` 可为：

- `flat`：超平坦（基岩 + 土 + 草，出生约 `(0,5,0)`）
- `sky`：空岛（虚空，chunk `(0,0)` 一整列 16×16 草土岛，出生 `[8, 64, 8]`）
- `ocean`：海洋（y 0–63 静止水 id 9，y≥64 空气，原点 16×16 小岛，出生 `[8, 64, 8]`）
- `nether`：地狱（维度 1，虚空 + 原点地狱岩岛，出生 `[8, 64, 8]`）
- `end`：末地（维度 2，虚空 + 原点末地石岛，出生 `[8, 64, 8]`）

启动时同时打开五个平级世界：配置里的 `WorldName`（默认 `world`，`flat`）、`sky`、`ocean`、`nether`、`end`。新建 `world.json` 时写入对应生成器；已有文件则沿用其中的 `generator`。

新建主世界时用配置里的出生点；空岛/海洋/地狱/末地出生点为 `[8, 64, 8]`（岛中央）。之后以 `world.json` 为准。

## 区域文件 `.gmr`

32×32 列一个文件，扇区 4096 字节。

- 魔数 `GMR1`，版本 1
- 1024 个槽：`offsetSectors(24bit) | sectorCount(8bit)`
- 槽数据：`uncompHint u32` + `compLen u32` + zlib 列载荷
- 整文件写到 `.tmp` 再 `rename`

列压缩前只存非空 subchunk 的 id/data、heightMap、biomes，不存光照（加载时天空光填 `0xFF`）。

只有 `SetBlock` 置脏的列才写盘。纯生成的超平坦列不占磁盘。列二进制格式不包含 tile / 实体。

## tiles.json

箱子（id 54）、末影箱（id 130）、熔炉、告示牌和床（id 26）是方块实体。`FullChunkData` 在 extraData 之后拼接 PocketMine 同款 **network little-endian NBT**（compound：`id` + `x/y/z`，床加 `color`，配对的箱子加 `pairx/pairz`）；放置时再发 `BlockEntityData`（0x38）。没有 tile 时 1.1 客户端重进经常不画箱子/床，看起来像方块没存。

- 箱子 27 格写在 `items` 里。点箱子发 `ContainerOpen`（type 0）+ `ContainerSetContent`，`ContainerSetSlot` 写回 tile。
- 大箱子：两个同朝向、并排的箱子互相记着对方的 X、Z（`paired`、`pairX`、`pairZ`），窗口是拼起来的 54 格。两边必须互相指着才算配对，只有一边记着按单箱处理，打开时顺手修掉。
- **末影箱的 tile 没有 `items`**：它的 27 格属于玩家，存在玩家 JSON 的 `enderChest` 里，所有末影箱方块共用同一份；tile 只是为了让客户端把箱子画出来。
- **工作台（id 58）没有 tile**，只是方块。点工作台只开合成窗（type 1），不编造库存。
- 破坏箱子时格内物品变成掉落物。

不做上床睡觉。

## 区块卸载

只加载不释放的话，地图跑大了内存会一直涨。每 10 秒（`chunkSweepInterval`）在后台扫一遍：每个在线玩家周围「视距和随机刻范围（4 个区块）里大的那个，再加 2 圈边距」留着，其余的存盘后从内存移走；没有玩家的世界清空。

- 脏区块必须先存成功才能移走。存失败、或者那个世界没有存储，就留在内存里，下一轮再试。
- 存盘是「先清脏标记、再写盘」，存的过程中又有人改了，标记会重新立起来，这个区块这一轮不会被移走。
- 写方块如果撞上区块恰好被卸载，会从盘上读回再写一遍（`withChunk`），最多重做 8 次。
- 存盘和卸载共用 `World.persistMu`，免得区块在新数据落盘之前被读回旧版本。
- 没改过的区块（纯生成的）不存盘，直接移走，再要时按坐标重新生成。

## entities.json

只存掉落物（物品 id/meta/count、坐标、速度、捡起延时、存活时间）。不存生物。进服后灌回内存并分配新的 RuntimeID。

## 玩家 JSON

按 UUID 一人一文件，字段包括坐标、维度、世界名、游戏模式、36 格背包、手持槽、饥饿状态，以及用过末影箱才有的 `enderChest`（27 格，全空不写）。

进服时先读 JSON 再出生；`PlayStatus PLAYER_SPAWN` 之后才发 `ContainerSetContent`。1.1 客户端要求 **45 格**（36 真实 + 9 个空气垫）以及 hotbar 映射 **9–17**（真实下标 +9）。只发 36 格且映射 0–8 时，HUD 快捷栏是空的，打开背包才看得到物品。

放置成功后服务端扣手持数量，并写回该格。客户端的 `ContainerSetSlot`（0x32）按 `slot` 覆盖对应格子（忽略 36–44 垫格）。`MobEquipment` 的 inventorySlot 通常是 9–44，要减 9 再写入。

## 何时落盘

| 时机 | 内容 |
|------|------|
| 新玩家首次进服 | 立刻写玩家 JSON |
| 断开连接 | 写该玩家，并刷一次该世界的脏列 + tiles.json + entities.json |
| 每 `PlayerSaveSeconds` 秒（默认 600） | 所有在线玩家背包/坐标 |
| 每 `AutosaveSeconds` 秒（默认 30） | 全部已加载世界的脏列 + tiles.json + entities.json + 各自 world.json |
| SIGINT / SIGTERM（`Server.Stop`） | 玩家 + 世界 |

## 复测

1. 放几块石头，关服再开，方块还在。
2. 改坐标/背包后重进，应回到上次位置和物品。
3. 从未改过的区块在 `overworld/` 下不应出现 `.gmr`。
4. 放箱子、往里面塞东西、放床，退出再进：箱子/床还在，箱内物品还在。工作台只是方块，重进后仍在（靠列存盘）。
5. 丢几个物品，退出再进：掉落物还在地上。
6. `/world ocean` 后近处水面应陆续出现，不应在贴脸处永远是虚空。

## 已知限制

- 不写生物。掉落物走 `entities.json`，箱子/床走 `tiles.json`。
- 区块不卸载，只刷脏列。
- 地狱/末地是独立世界，不是套在主世界或海洋里面的维度。
